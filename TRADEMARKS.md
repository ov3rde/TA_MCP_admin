# Trademark And Project Name Policy

- The source code is open source under `Apache-2.0`.
- The project name, logos, and branding remain identifiers of the original project and its maintainers.

## Permitted Use

- You may refer to this project by name to describe compatibility, origin, or factual history.
- You may say that a fork is "based on TA MCP Admin" or "compatible with TA MCP Admin".

## Prohibited Use

- Do not present a fork, modified package, or hosted service as the official project when it is not maintained by the original project maintainers.
- Do not use the project logo, publisher identity, or Splunkbase listing text in a way that implies endorsement.
- Do not reuse the same app branding for materially modified builds without making the fork or derivative status obvious.

## Forks And Redistributed Builds

- Rename forks or prominently mark them as unofficial when behavior, support model, or security posture differs from the upstream project.
- Keep your own contact, support, and release notes separate from the upstream project.
