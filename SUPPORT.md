# Support

## Support Model

- This app is published without any obligation to provide user support, troubleshooting, consulting, training, maintenance, or custom development.
- No commercial support, uptime commitment, warranty, indemnity, or service level is provided through this repository unless maintainers explicitly state otherwise in writing.
- Opening an issue, publishing contact details, or listing the app on GitHub or Splunkbase does not create a support contract or a duty to respond.

## Where To Ask For Help

- GitHub issues are only the default public channel for bug reports, packaging issues, and documentation gaps.
- Maintainers may respond on a voluntary, best-effort basis, but there is no entitlement to a reply, fix, workaround, or release date.
- If you publish the app on Splunkbase, keep the Splunkbase `Contact` and `Support` fields aligned with this file and `README.md`.

## What To Include

- App version and build number
- Splunk version and deployment type
- Clear reproduction steps
- Relevant redacted logs or screenshots

## What Not To Post Publicly

- Splunk management tokens
- MCP bearer tokens
- Customer data
- Private backend URLs that should not be disclosed
